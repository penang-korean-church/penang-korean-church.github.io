# 주일 소식 포스트 만들기

매주 토요일쯤 사용자가 그 주 주보 텍스트를 붙여넣는다. 할 일은 `_posts/`에 지난주와 같은 모양의 포스트를 하나 만드는 것이다. 이 스킬의 규칙은 대부분 사용자가 실제로 한 번씩 고쳐 달라고 했던 것들이라 그대로 따르는 게 가장 빠르다.

## 1. 시작 전

- `git fetch && git pull --ff-only` 를 먼저 한다. 사용자는 다른 기기에서도 푸시하므로 로컬이 뒤처져 있는 경우가 흔하다.
- 가장 최근 `_posts/YYYY-MM-DD-<month>-weekN-news.md` 를 읽는다. 이게 템플릿이다. 이모지, 섹션 구분선(`---`), 항목 표기 방식(`- **일시**: …`)을 그대로 따른다.
- 이미 있는 행사 포스트(`category: "행사"` 또는 `"공지"`, `pinned_until` 있음)를 `ls _posts` 로 확인해 둔다. 주보에 그 행사가 다시 나오면 새로 쓰지 말고 링크를 건다.

## 2. 파일과 front matter

- 파일명: `_posts/YYYY-MM-DD-<영어 월>-weekN-news.md` (예: `2026-10-25-october-week4-news.md`). N은 그 달 몇 번째 주일인지.
- `title: "2026년 10월 25일(주일) 소식"`, `date`, `category: "주보"`, `tags`(주보·교회소식·월 + 그 주 항목 키워드), `summary`(항목 제목들을 쉼표로 나열).
- `last_modified_at` 은 커밋 훅이 채우므로 지난주 값을 그대로 두거나 생략해도 된다.
- 전체 뼈대와 고정 하단 섹션은 `references/post-template.md` 에 있다. 하단 세 섹션(예물 안내 · 주차 안내 · 협력 및 후원)은 매주 글자 하나 바꾸지 말고 그대로 복사한다.

## 3. 본문 작성 규칙

**빼는 것.** 주보 맨 위의 📣 인사말("예수 그리스도를 인생의 주인으로…")과 성경 구절 묵상 섹션(예: "그와 함께 머물기 / 요한복음 1:39")은 넣지 않는다. 매주 똑같은 상용구라 사용자가 빼 달라고 했다. 첫 번째 소식 항목으로 바로 시작한다.

**이름 마스킹.** 평신도 이름은 가운데 글자를 `\*` 로 가리고 직분을 괄호로 붙인다: `김\*옥(권)`, `장\*훈(집)`, `이\*수(성도)`. 백슬래시가 있어야 마크다운이 강조로 해석하지 않는다. 목사·사모(한유림 사모)·선교사(정지영 선교사)는 공적 직분이라 그대로 쓴다. 보좌위원, 식사섬김 담당자, 생일·심방 대상 등 어디에 나오든 마스킹한다. 사용자가 "이름 마스킹해야 하는 거 알지?" 라고 확인한 적이 있을 만큼 중요하다.

**날짜 있는 모임에는 캘린더 링크.** 일시가 특정 날짜로 적힌 항목(기도회, 성찬예배, 새가족 모임, 기획위원회 등)은 일시 뒤에 `📅 [캘린더에 추가](…)` 를 붙인다. "매주일 오후 1시" 같은 정기 모임에는 붙이지 않는다. 링크는 손으로 만들지 말고 스크립트를 쓴다(인코딩 실수 방지):

```bash
python3 .agents/skills/weekly-news/scripts/gcal_link.py "11월 성찬예배" 2026-11-01 11:00 --markdown
python3 .agents/skills/weekly-news/scripts/gcal_link.py "10월 온가족 기도회" 2026-10-30 20:00 --details "페낭한인교회 10월 온가족 금요기도회" --markdown
```

기본 길이는 90분. 주일예배 관련 행사는 11:00 시작, 예배 후 모임은 13:30 시작으로 잡는다.

**여러 주에 걸친 행사는 별도 포스트로.** 찬양축제, 세례, 1인 1사역 모집, 여름성경학교처럼 포스터나 신청서가 있고 몇 주간 반복 안내되는 행사는 주일 소식 안에 길게 쓰지 않는다. 행사 포스트가 이미 있으면 섹션 제목 자체를 링크로 만든다:

```markdown
## ✝️ [추수감사절 세례]({{ '/news/2026/11/15/thanksgiving-baptism-2026/' | relative_url }})

1. **세례일**: 11월 15일(주일)
2. **신청**: [세례 안내 및 신청서 작성]({{ '/news/2026/11/15/thanksgiving-baptism-2026/' | relative_url }})
```

구글폼 주소는 주일 소식에 직접 넣지 않고 행사 포스트로 보낸다(사용자가 "폼 직접 링크는 이상하다"고 고친 적 있음). 행사 포스트가 아직 없고 포스터·폼이 같이 왔으면 `event-post` 스킬로 먼저 만든 뒤 링크한다. 포스터 이미지를 주일 소식에 끼워 넣는 것은 금지.

**속회 나눔지 링크.** 속회인도자 모임 항목에는 자료실과 그 주 나눔지 링크를 함께 쓴다. 나눔지가 같이 들어왔으면 `small-group-sheet` 스킬로 먼저 만들고 그 경로를 쓴다:

```markdown
- **속회 모임지**: 주보 및 홈페이지 [자료실]({{ '/resources/' | relative_url }}) → [10월 넷째 주 속회모임 나눔지]({{ '/resources/small-group/2026-10-26-october-week4/' | relative_url }})
```

**날짜 검산.** 주보에 "10월 3일(주일)" 처럼 요일과 날짜가 안 맞는 경우가 실제로 있었다. `cal` 로 확인해서 요일이 맞는 쪽으로 쓰고, 보고할 때 한 줄로 알린다. 지난주 소식과 같은 항목(정기 모임, 심방 기간 등)은 지난주 표현을 그대로 유지한다.

## 4. 검증과 보고

```bash
bundle exec jekyll build -q -d <scratchpad>/site
```

빌드 후 확인할 것: 새 포스트 URL(`/news/YYYY/MM/DD/<slug>/`)이 생겼는지, 본문 안의 `relative_url` 링크 대상 페이지가 실제로 빌드 결과에 있는지, 홈(`index.html`) 카드 순서가 의도대로인지(고정 포스트가 앞에 옴). 링크가 깨진 채 보고하면 사용자가 배포 후에야 알게 된다.

보고는 짧게: 만든 파일, 항목 수, 링크한 행사·나눔지, 날짜 검산에서 바꾼 것, 마스킹한 이름 수. 커밋은 하지 않는다.

## 5. 커밋은 "커밋 푸시해줘" 라고 할 때만

```bash
git fetch && git pull --ff-only
git add <파일들>   # git add -A 금지: 사용자가 작업 중인 다른 파일이 섞인다
git commit -F - <<'EOF'
10월 25일(주일) 교회소식 추가 - 종교개혁주일, 11월 성찬예배, 추수감사절 세례, 속회 나눔지

EOF
git push origin main
```

메시지는 한국어 한 줄 제목 + 주요 항목 나열. 푸시 후 커밋 해시와 반영될 URL을 알려준다.
